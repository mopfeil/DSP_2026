# DSP Exercises -- Engine Signals on Wokwi and JSLinux

Exercise sheets (LaTeX) and lab code for the master lecture
*Digital Signal Processing -- Using Automotive Engine Signals as a Guiding Example*
(`DSP_Lecture.pdf`).

## Layout

| Path | Content |
|---|---|
| `outline/Exercise_Outline.tex` | agreed outline of all sheets |
| `exercises/sheets/sheetNN.tex` | exercise sheets 00-12 incl. solutions |
| `exercises/dspex.sty` | layout + macros (`exercise`, `solution`, `\Wokwi`, `\JSLinux`, ...) |
| `exercises/Makefile` | `make` -> `exercises/pdf/SheetNN.pdf` and `SheetNN_solutions.pdf`; `make book` |
| `exercises/AUTHORING.md` | conventions for writing/extending sheets |
| `code/common/` | `engine_signals.h` (virtual engine), `asciiplot.h`, `csvio.h` |
| `code/jslinux/sheetNN/` | student templates (C, with TODOs) for JSLinux |
| `code/wokwi/sheetNN_*/` | student Wokwi projects (`sketch.ino`, `diagram.json`, ...) |
| `code/wokwi/chips/` | Wokwi custom chips `engine-sim` and `lambda-probe` (generated) |
| `code/solutions/` | reference solutions (do not hand out) |
| `tools/make_chips.sh` | regenerates the chips after changing `engine_signals.h` |
| `tools/wokwi_mock/` | PC stand-in for the Wokwi chip API to test chips with gcc |

## Building

```sh
cd exercises && make          # all sheets, with and without solutions
make sheet05                  # a single sheet
make book                     # all sheets in one PDF
```

## Virtual engine

`code/common/engine_signals.h` models a 4-cylinder engine: 60-2 crank wheel,
cam, knock sensor (6.5/10.5 kHz knock modes, valve impacts, noise), ion current
and a switching lambda sensor. The same model drives the Wokwi custom chip
`engine-sim` (via `tools/make_chips.sh`), so results in JSLinux and Wokwi agree.
After any change of the header run `tools/make_chips.sh` and copy the chip
files into the Wokwi projects that use them.

Testing a chip locally:
```sh
cd tools/wokwi_mock
gcc -std=c99 -I. run_chip.c ../../code/wokwi/chips/engine-sim.chip.c -lm -o run
ATTR_rpm=6000 ./run 0.05      # prints t_ns,pin,value of digital edges
```

## Status (2026-10-02)

* Sheets 00-12 written with full solutions; `make all` and `make book` build
  without errors (exercise book 37 pages, with solutions 92 pages).
* All 57 JSLinux C files (templates + solutions) compile with
  `gcc -std=c99 -Wall` and run (`alias_scan` needs arguments, e.g.
  `./alias_scan sim 5000 10 3000`; `filtertest` needs the `knock_filter.h`
  generated by `filterdesign`).
* All 27 Wokwi sketches compile with arduino-cli (Uno: `arduino:avr:uno`,
  ESP32: `esp32:esp32:esp32`, core 3.3). Uno RAM use is at most 1.25 KB.
* Numbers in the solutions come from running the reference code. For the
  Wokwi exercises they come from PC emulations of the sketches against the
  same engine model, not from the Wokwi simulator itself.

## To check once in the Wokwi browser simulator

* Custom chips compile in Wokwi (`timer_start_ns`, `pin_dac_write`,
  `attr_init_float`, slider controls) and the simulation speed is acceptable
  with the 50 kHz analog update rate of `engine-sim`.
* ESP32 (`wokwi-esp32-devkit-v1`, pins `esp:D34` etc.): whether the
  `analogRead` deadline loops hold 25 kHz (sheets 5, 10, 12) and 40 kHz
  (sheet 8); the sketches count late samples.
* Uno: Timer1/INT0 register code, ADC timing (~112 us), slide switch and
  button wiring in sheet 9, Q15 ISR load in sheet 10.
* Lambda loop periods in sheet 2 (predicted 0.58/1.00/1.80/3.40 s for
  Td = 100/200/400/800 ms).
* JSLinux: confirm gcc (or tcc) is available in the chosen VM image.
